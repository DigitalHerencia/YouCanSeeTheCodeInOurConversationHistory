# Hearth Codex Goal

Implement the complete Hearth system in this existing vault exactly from the supplied specification and handoff assets.

The result must provide:

- PARA-based execution: Project → Milestone → Phase → Task.
- Project-local Milestone Kanban.
- TaskNotes under `2.AREAS/SYSTEM/_Tasks` as execution truth.
- On-demand cadence and meeting generation under `2.AREAS/DAILY`.
- Generated Daily operating snapshots that populate derivable state and preserve human input.
- Zettelkasten as the active capture/processing workbench.
- Durable processed resources under `3.RESOURCES`.
- Archive lifecycle under `4.ARCHIVE`.
- Hearth Home, Command Center, Project Command Center, ZETTLECASTEN, Library, Code Lab, and Git/Vault destinations.
- Meta Bind controls for human-controlled properties.
- Automatic reconciliation of IDs, relations, provenance, progress, health, next action, and derived daily context.
- Migration of all current Notion projects, tasks, meetings, cadence definitions, and SOP semantics from the supplied export without guessing missing relations.
- All nine Maximal Template ontologies as Code Lab modules.
- DevCycles as Code Lab lessons.
- Real application construction in Code Space as the applied curriculum.
- Complete templates, workflow commands, Bases, dashboards, migration repair handling, and verification.

Read every file in this package before implementation.

Use `3.RESOURCES/Digital Herencia/` as the Notion source, `3.RESOURCES/template/` as the Maximal Template source, and the two TypeScripture directories as engineering doctrine.

Do not infer missing relations. Do not create a second task store. Do not make the owner manually maintain derived properties. Do not pre-generate cadence at scale. Do not invent unsupported plugin behavior.

Implementation is complete only when the acceptance contract passes and the final report records verified evidence, changed-file summary, migration counts, and runtime limitations.
