# Make the Public Shell Exploration-First

**Priority:** P1  
**Phase:** Showroom  
**Task status:** Backlog

## Outcome

Present authentication as a demonstrated capability rather than the gateway to exploring the template.

## Why This Exists

The product framing says authentication is an exhibit, not admission. Current shell emphasis still resembles a normal SaaS acquisition funnel.

## Execution Checklist

- [ ] Make Explore/demo navigation the dominant primary action.
- [ ] Reduce visual prominence of Sign In/Sign Up on the public shell.
- [ ] Keep auth surfaces discoverable through navigation and architecture/demo sections.
- [ ] Remove signed-out tenant-shell patterns that visually imply login is required to understand the app.
- [ ] Verify mobile shell retains the same exploration-first hierarchy.

## Acceptance Criteria

- [ ] A first-time visitor can enter the application demo without choosing authentication.
- [ ] Auth remains easy to find but is visually secondary.
- [ ] Public/mobile shells communicate showroom intent consistently.
