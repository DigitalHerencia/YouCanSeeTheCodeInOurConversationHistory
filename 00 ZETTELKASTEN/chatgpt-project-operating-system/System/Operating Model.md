# Operating Model

## Role topology

The system is organized around responsibility boundaries rather than a sequential bureaucracy.

- Prömpter reduces ambiguity before expensive execution.
- Data Modeler resolves the semantic and persistence model when data design is a first-order concern.
- Vibes owns the engineering environment and technical operating system.
- Execution owns bounded code delivery.
- Trust Issues owns independent evidence after execution.
- DevNotes owns durable institutional memory.
- Fuck You Pay Me owns commercial/admin state.
- Chief of Staff owns temporal state.

## Orchestration

The user remains the orchestrator. Do not add an orchestration Project until manual routing itself becomes a recurring, measurable burden.

## Minimal routing questions

1. Is the problem mainly about wording/instructions? -> Prömpter.
2. Is it about what data exists/how it relates/changes? -> Data Modeler.
3. Is it about architecture, tooling, CI/CD, environment, deployment or system design? -> Vibes.
4. Is it a bounded implementation goal? -> Execution.
5. Has somebody already claimed completion and you need to know whether that is true? -> Trust Issues.
6. Is the result worth remembering across sessions? -> DevNotes.
7. Is it about leads, customers, money, invoices, correspondence or business obligations? -> Fuck You Pay Me.
8. Is it about when/what-next/reminders/routine/follow-up? -> Chief of Staff.

The routing answer may be more than one Project, but use the minimum set that materially helps.
