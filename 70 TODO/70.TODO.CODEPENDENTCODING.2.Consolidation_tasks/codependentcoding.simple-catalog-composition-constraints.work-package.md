# Extract the final Simple catalog and enforce composition constraints

**Priority:** P1  
**Phase:** Catalog

## Outcome

Turn the hardened Maximal Template into a generation-ready library of discrete, source-backed Simples plus machine-readable composition rules.

## Checklist

- [ ] Inventory every reusable/canonical Simple from the hardened template.
- [ ] Give each Simple stable source path, responsibility, interfaces/contracts, relationships, constraints, variants, ownership, and readiness metadata.
- [ ] Encode required, permitted, conditional, prohibited, and invalid relationships as mechanically evaluable rules.
- [ ] Keep TypeScript/source files as implementation authority; metadata describes ownership, relationships, transforms, dependencies, constraints, and disposition.
- [ ] Support transitive dependency closure from pages/features into required workflows/server operations/helpers/backend machinery.
- [ ] Expose one relationship model to docs, Dataview/Obsidian, architecture validation, the per-Simple workbench, and the future Constitutor.
- [ ] Reject unsupported compositions explicitly rather than pruning until code happens to compile.

## Acceptance

- [ ] The reusable Lego pile is discrete, canonical, and source-backed.
- [ ] Composition rules classify proposed relations/configurations deterministically.
- [ ] Backend dependency closure is deterministic from selected composition.
- [ ] Docs/UI/validation/generation share one rules model.
