\# DevNotes Project Source



\## Purpose



DevNotes is a private, Git-backed Obsidian vault used as a durable knowledge system for software projects, agentic development workflows, product strategy, deep research, technical references, and creative writing.



This repository exists so the vault can be connected as a project source for AI-assisted work. Its job is not merely to store notes. Its job is to preserve operating context, organize source-of-truth project knowledge, and give future AI sessions enough structured information to work inside the vault without rediscovering the system from scratch.



DevNotes is the external memory layer for:



\- project source-of-truth notes

\- product contracts

\- technical architecture notes

\- Codex / agent work packages

\- deep research reports

\- documentation clippings

\- personal development notes

\- writing drafts

\- vault automation scripts

\- Obsidian operating workflows



\## Core Operating Model



The vault uses a hybrid protocol:



```txt

Numbered top-level folders       → stable navigation

Dendron-style dot notation       → semantic note identity

Zettelkasten capture             → atomic note growth

Contract-style documentation     → source-of-truth project rules

Obsidian properties              → machine-readable metadata

Dataview maps and dashboards     → operational surfaces

Git                              → versioning, rollback, review, agent context

```



The mental model:



```txt

folders     = neighborhoods

filenames   = semantic addresses

properties  = machine-readable metadata

links       = graph edges

maps        = operating surfaces

contracts   = source-of-truth rules

templates   = repeatable document shapes

\_OPS        = vault automation

```

| `supersedes` | Older notes replaced by this one |

| `created` | Creation date |

\## Important Obsidian Rule



Frontmatter must be the first thing in the file.



Correct:



```yaml

\---

title: Example

type: contract

tags:

&#x20; - projects/rateltd

\---

```



Incorrect:



```markdown

Some title first



\---

title: Example

\---

```



Incorrect YAML list syntax in frontmatter:



```yaml

tags:

\* projects/rateltd

```



Correct YAML list syntax:



```yaml

tags:

&#x20; - projects/rateltd

```

\## Agent Usage Rules



When working inside this repo, an AI agent should:



1\. Treat this file as the highest-level project source document.

2\. Treat `devnotes.home.md` as the vault homepage.

3\. Treat `90 OBSIDIAN/Contracts` as the governance layer for the vault.

4\. Treat `90 OBSIDIAN/OB-Templates/Contracts` as reusable document shapes.

5\. Preserve numbered top-level folders.

6\. Preserve dot-notation filenames for durable notes.

7\. Add valid Obsidian frontmatter to serious notes.

8\. Never place frontmatter below a title.

9\. Never use Markdown `\*` bullets inside YAML frontmatter lists.

10\. Prefer wikilinks for vault-internal links.

11\. Prefer Markdown links only for external URLs.

12\. Do not flatten project folders.

13\. Do not delete legacy material unless explicitly instructed.

14\. Use Git checkpoints before and after structural migrations.

15\. Write PowerShell automation into `\_OPS`.

16\. Keep source-of-truth project rules in project folders, not only in chat.

\## Markdown / YAML / JSON Philosophy



Use this separation:



```txt

Markdown = thinking and explanation

YAML     = structured planning and contracts

JSON     = execution state and logs

```



In practice:



\- `.md` files carry human-readable project memory.

\- `.yaml` files carry semi-structured contracts.

\- `.json` files carry runtime or agent state.

\- `.jsonl` files carry append-only logs.
