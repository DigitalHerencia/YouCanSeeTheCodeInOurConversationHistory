## Make constraints explicit so priorities stay real

**Intent**

Constraints are not weaknesses — they are *guardrails*. Ops makes them visible.

### Key Results

- **KR3.1:** Document and publish the following constraint classes:
    - Time (meeting load, weekly capacity)
    - Scope (max concurrent projects per team)
    - Cognitive load (max active tasks per owner)
- **KR3.2:** Any task that violates a constraint is:
    - flagged
    - re-scoped
    - or rejected
- **KR3.3:** No new project enters “In Progress” without explicit acknowledgment of constraints
