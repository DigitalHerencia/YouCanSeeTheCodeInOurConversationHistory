# DevNotes Unified System Blueprint

## Definition

DevNotes is a source-controlled knowledge-and-engineering operating environment whose durable substrate is Markdown, Properties, links, Git history, machine contracts, and connected evidence, and whose primary human interface is Obsidian.

The detailed role and interaction contract is [[Role Manifest Specification]].

## Four system surfaces

1. **TypeScripture™** supplies canonical doctrine and engineering knowledge.
2. **Codependent Coding™** realizes that doctrine as an engineering system, product family, generation model, implementation architecture, and vocabulary.
3. **Obsidian / DevNotes** is the durable human-and-machine operating environment.
4. **ChatGPT Projects + Codex** form the active specialized agent team.

## Common operating loop

**Human intent → structured knowledge → specification → orchestration → implementation → verification → durable context**

## Information architecture

- Folders establish the primary responsibility home.
- Properties represent useful mutable state and independent facets.
- Tags classify material without assigning ownership.
- Wikilinks/backlinks form durable semantic relationships.
- Typed relationships are used only when edge semantics matter.
- Bases retrieve and project the graph.
- Hearth composes the operating interface.
- Code Space exposes live implementation.

## Authority of volatile systems

Live systems remain authority for their own volatile facts. DevNotes preserves durable institutional context and provenance rather than pretending to replace GitHub, deployment platforms, financial providers, mail/calendar systems, or live source code.

## Derivation contract

**Role Manifest Specification → machine role registry → Hearth dashboard + ChatGPT Project launcher**

Machine and interface projections must not independently redefine the human role manifest. Disagreement is governance drift.
